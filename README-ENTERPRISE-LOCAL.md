# AI Observability Platform - Enterprise Local Lab

This branch extends the existing platform into a local, multi-node Kubernetes AIOps environment.

## Architecture

Client -> local DNS/hosts -> NGINX Ingress -> Kubernetes Services -> 3 FastAPI services -> PostgreSQL.

Services:
- auth-service
- catalog-service
- order-service
- ai-engine

Infrastructure:
- Kind multi-node Kubernetes
- CoreDNS
- NGINX Ingress
- Helm
- PostgreSQL
- Prometheus
- Grafana
- Loki
- Grafana Alloy
- OpenTelemetry
- Jaeger v2

## AI

The AI engine is a Kubernetes-aware SRE service. It collects pod state and events, queries Prometheus metrics, classifies known incident signatures, and optionally sends the evidence to a local Ollama model such as Qwen 2.5 3B.

The project does not use artificial RAG documents. RAG can be added after real runbooks and incident reports are generated by the platform.

## Run

From the repository root:

1. Create the cluster:
   ./scripts/create-cluster.sh

2. Build and load local images:
   ./scripts/build-images.sh

3. Install the platform:
   ./scripts/install-platform.sh

4. Deploy applications:
   ./scripts/deploy-app.sh

5. Add local host aliases:
   ./scripts/add-hosts.sh

6. Verify:
   ./scripts/verify.sh

Or run ./scripts/bootstrap.sh for all steps.

## Local endpoints

http://api.aiops.test/auth/health

http://api.aiops.test/ai/health

Use kubectl port-forward for Grafana and Jaeger if you want direct UI access.

## Incident tests

./scripts/test-incidents.sh crashloop
./scripts/test-incidents.sh oom
./scripts/test-incidents.sh imagepull
./scripts/test-incidents.sh pending
./scripts/test-incidents.sh clean

Then call:

curl -X POST http://api.aiops.test/ai/api/v1/analyze

The response contains the operational evidence and the RCA generated by deterministic rules or Ollama.
